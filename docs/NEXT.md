# 下一轮优先事项

目标：把当前本地开发版推进为可复验、差异边界清楚的申报候选。预计再投入 10–16 小时；以实际发现的问题重新估计，不把工时或测试数量当作审核保障。

| 顺序 | 工作 | 完成判断 |
|---|---|---|
| 1 | 扩展 RFC 2849 示例和错误变体，尤其控制项、空修改、重命名、字段歧义 | 每个支持/拒绝决策都有依据、输入、诊断及回归测试 |
| 2 | 对 all change types 引入第二个独立解析器对照 | 四类操作、控制有无值、顺序和字节均有真实对照记录 |
| 3 | 增强实用预检 | 优先实现可解释的 DN/RDN 语法诊断；明确不宣称 Schema 语义验证 |
| 4 | 提供真实文件可用性证据 | 在有授权且脱敏的导出样本上验证，保留失败案例与边界；没有真实样本时继续标合成数据 |
| 5 | 公开发布准备与复查 | 再查 mooncakes/GitHub 同类；写清与 moonldap 的互补；远端 CI、正式包及干净安装分别验证 |

核心取舍：先把文件读写、错误定位、安全写回和已有生态接入做扎实。控制语义、完整 Schema、网络同步、网页界面与自动执行迁移暂不扩展。

本轮已完成的代码可以作为选题变更说明中的事实；不能写成“全球首个”“没有竞争项目”“真实企业已使用”或“保证通过审核”。
