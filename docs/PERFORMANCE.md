# 规模与资源证据

运行 `node scripts/benchmark.mjs`，输出 `verification/local/performance.json`。固定生成 100、1,000、5,000、10,000 条内容记录，包括名称、属性及二进制值；每个规模/操作单独启动进程，预热一次、测量三次。先验证记录数、退出码和写出结果，再记录计时。

计时包含 Base64 传递、MoonBit 解析/预检、报告，以及 format 时的写回再解析核对；不含工具链编译或磁盘读写。内存是 Node 进程运行前后的 RSS，不是峰值，也不是核心库的精确分配量。

2026-09-15 本机：Windows x64，Node 24.13.0，AMD Ryzen 7 5800H；版本 0.1.0-dev.2。输入均为合成文件，10,000 条约 2.18 MB。不能据此宣称真实企业吞吐、无限流或优于其他库。

| 10,000 条记录 | 优化前中位耗时 | 优化后中位耗时 | 优化前运行后 RSS | 优化后运行后 RSS |
|---|---:|---:|---:|---:|
| check | 560.8 ms | 526.5 ms | 376.8 MiB | 334.2 MiB |
| format | 2,285.9 ms | 1,031.6 ms | 1,267.0 MiB | 577.0 MiB |

优化移除了写回核对中的两份完整 JSON 树，改成直接比较名称、操作顺序、控制项和属性字节；普通 check 不再创建最终不会输出的逐属性位置对象。前后均保留重新解析步骤。测试与独立对照用于确认结果没有改变。

前后 JSON 原始读数保存在本轮验证快照。三次测量不能替代统计性能研究，RSS 会受到垃圾回收与操作系统影响。当前 10,000 条写回仍占用数百 MiB，属于明确的改进空间。产品仍采用有上限的完整缓冲区，不承诺低内存流式处理；浏览器使用体验必须另外验证并设置合适的工作量限制。
