# 0.5.1 性能与稳定性复验

2026-09-21，Windows、Node.js 24.13.0，与 v0.5.0 同机比较。每个场景用独立进程预热一次、测量七次；进一步交替版本顺序测量三轮，以下为配对耗时比的中位数。负值为本次观察更快，正值为更慢。

| 合成场景 | 配对耗时变化 | 复验 |
|---|---:|---|
| check-100 | -3.2% | 未超过 10% 退化门槛 |
| format-100 | -5.0% | 未超过 10% 退化门槛 |
| check-1000 | 11.8% | 触发复测：3.8%，未持续超过 10% |
| format-1000 | 6.2% | 未超过 10% 退化门槛 |
| check-5000 | -3.8% | 未超过 10% 退化门槛 |
| format-5000 | 1.3% | 未超过 10% 退化门槛 |
| check-10000 | 3.8% | 未超过 10% 退化门槛 |
| format-10000 | -0.4% | 未超过 10% 退化门槛 |
| folded | -4.8% | 未超过 10% 退化门槛 |
| risk-review | 3.8% | 未超过 10% 退化门槛 |
| compare | -4.6% | 未超过 10% 退化门槛 |

批处理 50 个小文件包含实际 CLI 启动和文件读取，本次配对观察约减少 25% 耗时；其子进程 RSS 未测量。多数核心场景与旧版接近，不宣传普遍翻倍提速。早期顺序测量曾出现约 50% 提升，后续顺序测量方向反转，因此只保留为波动证据，不采用其百分比作宣传。

确定的分配改进：3 字节文件读取缓冲区由固定 8 MiB + 1 字节变为 4 字节；文件增长仍逐步扩容且最多读到限制加一个探测字节。浏览器 Worker 不再同时传送序列化报告及解析后对象。所有风险策略和写出往返核对保留。

RSS 是进程运行前后观察，不是峰值；浏览器堆观察仅覆盖主线程，不能据此声称无泄漏。没有强制 GC，没有更改输入上限。全部输入为合成数据，不代表企业吞吐或其他机器结果。

复现：先运行 `npm run build`、`python scripts/baseline-verify.py`，再运行 `node scripts/performance-compare.mjs`。单版规模观察使用 `node scripts/benchmark.mjs`。共享 CI 记录结果，不设置毫秒阈值。完整原始数据见 [本轮证据](../verification/2026-09-21-v0.5.1/README.md)。

# 规模与资源证据

运行 `node scripts/benchmark.mjs`，输出 `verification/local/performance.json`。固定生成 100、1,000、5,000、10,000 条内容记录，包括名称、属性及二进制值；每个规模/操作单独启动进程，预热一次、测量三次。先验证记录数、退出码和写出结果，再记录计时。

计时包含 Base64 传递、MoonBit 解析/预检、报告，以及 format 时的写回再解析核对；不含工具链编译或磁盘读写。内存是 Node 进程运行前后的 RSS，不是峰值，也不是核心库的精确分配量。

2026-09-15 本机：Windows x64，Node 24.13.0，AMD Ryzen 7 5800H；版本 0.1.0-dev.2。输入均为合成文件，10,000 条约 2.18 MB。不能据此宣称真实企业吞吐、无限流或优于其他库。

| 10,000 条记录 | 优化前中位耗时 | 优化后中位耗时 | 优化前运行后 RSS | 优化后运行后 RSS |
|---|---:|---:|---:|---:|
| check | 560.8 ms | 526.5 ms | 376.8 MiB | 334.2 MiB |
| format | 2,285.9 ms | 1,031.6 ms | 1,267.0 MiB | 577.0 MiB |

优化移除了写回核对中的两份完整 JSON 树，改成直接比较名称、操作顺序、控制项和属性字节；普通 check 不再创建最终不会输出的逐属性位置对象。前后均保留重新解析步骤。测试与独立对照用于确认结果没有改变。

前后 JSON 原始读数保存在本轮验证快照。三次测量不能替代统计性能研究，RSS 会受到垃圾回收与操作系统影响。当前 10,000 条写回仍占用数百 MiB，属于明确的改进空间。产品仍采用有上限的完整缓冲区，不承诺低内存流式处理；浏览器使用体验必须另外验证并设置合适的工作量限制。
