# 三分钟演示与个人复验

三个场景均为合成数据，不是真实企业客户。启动方式见根 README 和 `web/README.md`。先保留当前编辑，再切换示例；页面没有自动保存。

## 0:00–1:00：先看出会删除什么

打开工作台默认“账号变更计划”。应出现 2 条记录、3 项变更审阅、1 项删除拦截，导出禁用。

说明：`replace: mail` 替换整个属性值集合；没有指定值的 `delete: description` 删除整个属性；最后一条删除目录条目。点击各项“定位原文”，展示物理行号与原文相对应。

重点是操作含义和可追溯位置，不是简单统计关键字。审阅不会展示属性值，也不假装知道服务器内的旧值。

## 1:00–2:00：修正问题后才生成文件

选择“名称错误排查”。定位有问题的 DN，将 `dn: cn=Alice,` 改为 `dn: cn=Alice`。编辑后旧报告失效，导出仍禁用；点击“重新检查”，成功后导出。

再将编辑区替换为下面的内容，重新检查。应报告分析不完整并禁止导出。说明外部引用没有被读取，不能把未分析数据算作通过。

```ldif
version: 1
dn: cn=Demo
cn: Demo
photo:< file:///never-read
```

## 2:00–3:00：生态接入与工具验证

选择“迁移计划”，查看改名/移动的审阅和位置。命令行运行：

```text
node scripts/demo.mjs
node dist/moonldif.js review examples/03-migration-plan.ldif --format json
node scripts/test-moonldap.mjs
```

最后一个命令需先按 README 准备固定版本的可选依赖。说明 JSON 可供其他工具消费，MoonLDIF 负责文件层，MoonLDAP 负责协议模型；当前测试是离线映射和 BER 往返。

## 可以自行确认的五件事

1. 错误或不完整输入无法导出；取消删除策略也不能绕过语法错误。
2. 编辑或修改选项后，旧的成功结果不会继续启用导出。
3. 中文文件名可打开，Base64 属性字节不会被替代字符改写。
4. 导出的是新文件；CLI 再次读取后可核对记录和操作顺序。
5. 将三场景输出和证据页对照，而不是只看绿色提示。

尚不能演示：真实企业目录导入、Schema/权限验证、LDAP 服务端执行成功。这些不是当前范围。答辩时需能解释源位置、字节模型、退出码优先级、写回核对与互操作差异。
